## What is this?

Swara is a static web app — no server, no database, no backend. It streams your `.m4a` music files directly from GitHub Releases. Metadata is auto-generated by a GitHub Action in the `m4a-db` repository and served via jsDelivr CDN.

**Architecture at a glance:**

```
Your music files (.m4a + cover.webp)
         ↓  upload as GitHub Release assets
    m4a-db (public repo)
         ↓  GitHub Action runs automatically
    data/albums.json + data/<tag>.json generated
         ↓  committed to m4a-db main branch
    jsDelivr CDN serves JSON (fast, cached)
         ↓  Swara app fetches JSON
    Browser streams .m4a directly from GitHub Releases
```

## Features

- 🔒 **Passphrase gate** — lightweight protection, no accounts
- 📀 **Album library** — cover art, metadata, track lists
- ▶️ **Music player** — seekbar, prev/next, shuffle, repeat
- 💜 **Liked songs** — saved to localStorage, no backend
- 🔍 **Search** — full-text across albums and tracks
- 📱 **Mobile-first** — thumb-friendly, touch-optimized
- 🌙 **Dark mode only** — matte black, blue accent
- 📲 **PWA** — installable, offline shell, lockscreen controls
- 🎵 **Media Session API** — lockscreen metadata + controls on iOS/Android

## Setup

### 1. Fork / clone the swara repo

```bash
git clone https://github.com/Bharadwaja1557/swara
cd swara
npm install
```

### 2. Set up your passphrase

Generate a SHA-256 hash of your chosen passphrase:

```bash
# macOS/Linux
echo -n "yourpassphrase" | sha256sum | awk '{print $1}'

# Node.js
node -e "const c=require('crypto');console.log(c.createHash('sha256').update('yourpassphrase').digest('hex'))"
```

Add it to GitHub repo secrets:
- Go to **Settings → Secrets and variables → Actions**
- Add secret: `PASSPHRASE_HASH` = the hash you generated

### 3. Enable GitHub Pages

- Go to **Settings → Pages**
- Source: **GitHub Actions**

The deploy workflow (`.github/workflows/deploy.yml`) handles everything.

### 4. Local development

```bash
cp .env.local.example .env.local
# Edit .env.local with your passphrase hash
npm run dev
```

## Adding Music

### File naming format

```
TRACK--SINGERS--TITLE.m4a
```

| Part | Format | Example |
|------|--------|---------|
| `TRACK` | 2-digit padded number | `01`, `12` |
| `SINGERS` | `_` = space, `+` = multiple artists | `Arijit_Singh+Shreya_Ghoshal` |
| `TITLE` | `_` = space | `Tum_Hi_Ho` |

**Important rules:**
- `_` → space
- `+` → artist separator
- `.` → preserved (for `A.R. Rahman`, `K.K.`)
- `-` → preserved (for `Dil-E-Nadaan`, `Shankar-Ehsaan-Loy`)
- `--` → segment separator (track `--` artists `--` title)

**Examples:**

| Filename | Track | Artists | Title |
|----------|-------|---------|-------|
| `01--Arijit_Singh--Tum_Hi_Ho.m4a` | 1 | Arijit Singh | Tum Hi Ho |
| `01--A.R_Rahman+Sid_Sriram--The_Life_of_Ram.m4a` | 1 | A.R Rahman, Sid Sriram | The Life of Ram |
| `12--Shreya_Ghoshal+Udit_Narayan--Dil-E-Nadaan.m4a` | 12 | Shreya Ghoshal, Udit Narayan | Dil-E-Nadaan |
| `05--K.K--Pal_Pal_Dil_Ke_Paas.m4a` | 5 | K.K | Pal Pal Dil Ke Paas |

### Creating a release in m4a-db

1. Go to the `m4a-db` repo → **Releases → Draft a new release**
2. Set the tag (this becomes the album ID, e.g. `bollywood-2024`)
3. Set the release name (this becomes the album title)
4. **Optional** — add metadata in the release body:
   ```
   Year: 2024
   Genre: Bollywood
   Artist: Various Artists
   Description: A collection of Bollywood hits.
   ```
5. Upload your `.m4a` files + `cover.webp` as release assets
6. Publish the release

The GitHub Action in `m4a-db` will automatically:
- Scan all release assets
- Parse filenames
- Generate `data/albums.json` and `data/<tag>.json`
- Commit to main
- (Optional) Trigger a Swara rebuild

### Setting up m4a-db automation

Copy `m4a-db-action/generate-metadata.yml` to your `m4a-db` repo:

```
m4a-db/
└── .github/
    └── workflows/
        └── generate-metadata.yml   ← copy this file here
```

The workflow runs automatically on every release event.

## Environment variables

| Variable | Required | Description |
|----------|----------|-------------|
| `NEXT_PUBLIC_PASSPHRASE_HASH` | Yes | SHA-256 hex hash of your passphrase |
| `NEXT_PUBLIC_MUSIC_DB_REPO` | No | `owner/repo` of m4a-db (default: `gajala-sonic-solutions/m4a-db`) |
| `NEXT_PUBLIC_BASE_PATH` | No | If deploying to a subdirectory (e.g. `/swara`) |

In CI (GitHub Actions), set these as:
- **Secrets**: `PASSPHRASE_HASH`
- **Variables**: `MUSIC_DB_REPO`

## Local metadata testing

Test the filename parser:

```bash
node scripts/generate-metadata.js --self-test
```

Generate metadata from a local folder:

```bash
node scripts/generate-metadata.js \
  --release-tag bollywood-2024 \
  --release-title "Bollywood Hits 2024" \
  --files-dir ./my-music \
  --repo gajala-sonic-solutions/m4a-db \
  --year 2024 \
  --genre Bollywood \
  --output ./data
```

## Triggering Swara rebuild from m4a-db

To auto-rebuild Swara when you add new music:

1. Create a fine-grained PAT with `repo: write` access to the swara repo
2. Add it to m4a-db secrets as `SWARA_DISPATCH_TOKEN`
3. Uncomment the "Trigger Swara rebuild" step in `m4a-db-action/generate-metadata.yml`
